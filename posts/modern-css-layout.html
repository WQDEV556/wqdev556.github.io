用现代 CSS 写一个不会塌的布局

2026 年 9 月 28 日 7 分钟阅读 技术

「布局塌了」通常不是代码写错了，而是约束没有表达清楚： 谁负责换行、谁负责收缩、最小宽度是多少、字号什么时候变。 现代 CSS 的好处是，这些约束可以直接写进声明里，不需要靠一堆媒体查询兜底。

这篇用四个小片段，把我日常最常用的写法整理一遍。

一、宽度：别写死，写区间

容器宽度最常见的错误是 width: 1200px。它在大屏上两侧空得慌，在手机上直接横向滚动。 现在只需要一行：

css
.wrap {
  width: min(100% - 2.5rem, 1080px);
  margin-inline: auto;
}

min() 的意思是「两者取小」：屏幕窄时留出 1.25rem 的边距，屏幕宽时封顶 1080px。 不需要媒体查询，也不会出现「刚好在断点附近抖动」的尴尬。

二、页面骨架：用 Grid 表达列

两栏、三栏布局我会直接上 Grid，让「列」这件事显式声明出来。 关键是 minmax(0, 1fr)——中间的 0 允许内容收缩， 否则长单词、代码块、表格会把整列撑破。

css
.page {
  display: grid;
  grid-template-columns: minmax(0, 1fr);
  gap: clamp(1rem, 2.5vw, 2rem);
}

@media (min-width: 60rem) {
  .page {
    /* 侧栏 220px，正文自适应，再来一个侧栏 */
    grid-template-columns: 220px minmax(0, 68ch) 220px;
    justify-content: center;
  }
}

68ch 是我很喜欢的一个细节：它把正文限制在「一行大约 68 个字符」， 这是阅读舒适度的经典区间。窗口再宽，行也不会长得让人串行。

三、字号：用 clamp() 做流体排版

标题字号以前要写三四条媒体查询。现在一条就够，中间那个 vw 项负责随视口插值：

css
h1 {
  font-size: clamp(2rem, 1.2rem + 3.2vw, 3.4rem);
  line-height: 1.15;
  text-wrap: balance;
}

/* 正文：小屏别小于 16px，大屏别大于 19px */
body {
  font-size: clamp(1rem, 0.96rem + 0.2vw, 1.19rem);
  line-height: 1.75;
}

注意 clamp(最小值, 理想值, 最大值) 的顺序。 理想值里混一点 rem 是刻意的：如果只用 vw，用户放大页面时字号不会跟着变大，可访问性会翻车。

另外强烈建议给标题加上 text-wrap: balance，它会自动把多行标题断得更均匀，成本为零。

四、组件：用容器查询，而不是视口查询

这是近几年最改变写法的一个特性。卡片放在侧栏和放在主区域，宽度完全不同； 用媒体查询只能根据「窗口多宽」猜，用容器查询则可以直接问「我爹多宽」：

css
.card-list {
  container-type: inline-size;
}

.card {
  display: grid;
  gap: 1rem;
}

/* 只有当这张卡片所在的容器 ≥ 34rem 时，才变成左右结构 */
@container (min-width: 34rem) {
  .card {
    grid-template-columns: 180px minmax(0, 1fr);
    align-items: center;
  }
}

组件因此变得「可搬运」：同一个 .card 放进窄侧栏自动竖排，放进宽主区自动横排， 完全不需要为它单独写一套断点。

五、几个容易忘的收尾

  • min-width: 0：flex / grid 子项里有长内容时，不加这句就缩不下去。我为此浪费过一个下午。
  • aspect-ratio：封面图别再用 padding-top 百分比的老 hack 了。
  • dvh 而不是 vh：移动端浏览器地址栏收起时，100vh 会露出一截空白。
  • gap：能不用 margin 就不用，布局容器里的间距交给容器自己管。
  • :focus-visible：去掉 outline 之前，先给它一个更好看的替代。

小结

这些写法没有一个需要框架。它们的共同点是：把约束写在声明里，而不是写在脑子里。 布局之所以「塌」，往往是因为我们默认了一些浏览器并不知道的前提。

把前提写出来，页面就稳了。剩下的，交给浏览器。
