从零把这个博客发布到公网：四种免费方案

2026 年 10 月 18 日 9 分钟阅读 部署

这个站是纯静态的：只有 HTML、CSS、JS 和几个 XML 文件，没有后端、没有数据库、没有构建步骤。 这意味着它可以被任何一台能发文件的机器托管——而且大部分方案免费。

下面四条路线，我都实际用过。如果你只想最快看到效果，跳到 Netlify 那节，拖一个文件夹就行。

开始之前：先把这三处改成你自己的

  1. sitemap.xml 和 rss.xml 里的 https://example.com，换成你的域名（没有域名就换成平台给的地址）。
  2. about.html 里的邮箱、GitHub 链接、自我介绍。
  3. index.html 里的站点名、作者名、统计数字。

另外，所有链接都是相对路径（../assets/css/style.css 这种）。 请保留这个写法——它让站点既能放在域名根目录，也能放在 /repo-name/ 这样的子路径下， 而不用改任何一行代码。

方案一：GitHub Pages（最适合放代码的地方）

免费、稳定、自带 HTTPS，适合已经用 GitHub 管代码的人。两种站点类型要分清：

类型仓库名访问地址
用户站你的用户名.github.iohttps://你的用户名.github.io/
项目站任意名字，如 bloghttps://你的用户名.github.io/blog/

步骤（项目站为例）：

bash
# 1. 在 GitHub 新建一个空仓库，比如 blog（不要勾选 README）
# 2. 在本地站点目录里初始化并推送
cd blog
git init
git add .
git commit -m "init: my blog"
git branch -M main
git remote add origin https://github.com/你的用户名/blog.git
git push -u origin main

然后进仓库 Settings → Pages：Source 选 Deploy from a branch， 分支选 main，目录选 / (root)，保存。 等一两分钟，页面顶部会出现访问地址。

注意：项目站必须把仓库名当作子路径，而本站所有链接都是相对的，所以不需要额外配置。 如果你以后改用绝对路径（以 / 开头），项目站就会 404——这是最常见的翻车点。

方案二：Netlify（最快，拖拽即可）

不碰 Git 也能上线。打开 app.netlify.com/drop， 把整个 blog 文件夹拖进去，几秒后就会得到一个 https://随机名字.netlify.app 的地址。

想改名或绑定自己的域名：

  • Site configuration → Change site name：把随机名改成 linjian，地址就变成 linjian.netlify.app。
  • Domain management → Add a domain：填自己的域名，按提示去域名商加一条 CNAME 记录。

拖拽上传适合试用。要长期维护，建议在 Netlify 里连接 GitHub 仓库， 之后每次 git push 自动重新发布。

方案三：Vercel（命令行一条命令）

装好 Node.js 后：

bash
npm i -g vercel      # 或者直接用 npx vercel
cd blog
vercel                # 首次会引导登录、确认项目名
vercel --prod         # 发布到正式地址

它会问你几个问题，全部回车用默认值即可。因为本站没有构建步骤， Build Command 留空、Output Directory 填 . 就行。 默认域名形如 https://blog-xxx.vercel.app，同样可以绑自定义域名。

方案四：Cloudflare Pages（国内访问相对友好）

GitHub Pages 在国内偶尔会抽风。Cloudflare Pages 免费、带宽不限， 对国内的可达性通常更好一些（并不保证，但通常更稳）。

  1. 登录 Cloudflare Dashboard → Workers & Pages → Create → Pages → Connect to Git。
  2. 选你的仓库，框架预设选 None，构建命令留空，输出目录填 /。
  3. 保存并部署，得到 https://项目名.pages.dev。

如果不想连 Git，也可以用 Wrangler 直接上传：

bash
npm i -g wrangler
wrangler pages deploy . --project-name=my-blog

绑定自己的域名

四个平台的流程几乎一样，核心只有两步：

  1. 在平台后台添加域名，它会告诉你加什么 DNS 记录（通常是 CNAME 指向平台给的地址）。
  2. 去域名商（阿里云、腾讯云、Namecheap、Cloudflare 等）的 DNS 设置里加上那条记录，等待生效（几分钟到几小时）。

HTTPS 证书这些平台都会自动签发和续期，不用自己配。 如果域名本身就托管在 Cloudflare，记得把代理状态（小云朵）打开或关闭都试一次—— 有时候「仅 DNS」模式反而更快生效。

上线检查清单

  • 首页能打开，CSS 正常加载（没有裸 HTML 的白板效果）。
  • 点进任意一篇文章，再点「返回首页」能回来。
  • 手机宽度下菜单能展开，卡片变成单列。
  • 右上角切换深色模式，刷新后仍然是深色。
  • 访问一个不存在的地址（比如 /abc），能看到自定义 404 页（GitHub Pages / Netlify / Cloudflare 都支持）。
  • /sitemap.xml 和 /rss.xml 能正常打开，没有 XML 解析错误。
  • 把地址丢给 PageSpeed Insights 跑一次，看看有没有明显问题。

要不要自动化？

现在这个规模（四篇文章、手写 HTML），手动上传完全够用，而且更可控。 等你写到二十篇、开始觉得「改首页卡片好烦」的时候，再考虑引入静态站点生成器 （Hugo、Astro、Eleventy 都行）和 GitHub Actions 自动构建。

工具是为了减少摩擦，不是为了增加仪式感。能让你持续写下去的方案，就是最好的方案。
